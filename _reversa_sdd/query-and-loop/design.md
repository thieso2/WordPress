## Main Flow

1. **404 exemption cascade** — Default is to 404. Exemptions for admin/robots/favicon, for found posts with valid pagination, and for empty archives whose queried object exists. Paged empty archives are never exempt.
   Source: `wp-includes/class-wp.php:724` 🟢
2. **seven-clause SQL assembly with double filtering** — fields, join, where, groupby, orderby, distinct and limits are each filterable early and again as *_request, plus posts_clauses and posts_request over the whole set. 34 filters total.
   Source: `wp-includes/class-wp-query.php:1900` 🟢
3. **split query** — SELECT ID then hydrate individually from cache, instead of SELECT wp_posts.*. Only for unfiltered queries with either a persistent object cache or posts_per_page < 500.
   Source: `wp-includes/class-wp-query.php:3383` 🟢
4. **SQL_CALC_FOUND_ROWS pagination** — found_posts read via SELECT FOUND_ROWS(); max_num_pages = ceil(found_posts / posts_per_page). Forces MySQL to count the full match set.
   Source: `wp-includes/class-wp-query.php:3692` 🟢
5. **stopword-filtered LIKE search** — Terms are trimmed, single a-z/dash tokens and stopwords dropped, survivors become leading-wildcard LIKE conditions. No index usable, no ranking.
   Source: `wp-includes/class-wp-query.php:1556` 🟢
6. **lazy loop cache priming** — On the first the_post() only, reduce results to ids and bulk-prime post, term, meta and author caches. The loop-level N+1 defense.
   Source: `wp-includes/class-wp-query.php:3768` 🟢

## Alternative Flows

- **BR-QUERY-02:** Private query vars such as post_status, post__in and fields can never be set from the URL. This is the boundary that keeps drafts private. 🟢
- **BR-QUERY-03:** Admin, robots.txt and favicon requests never 404. 🟢
- **BR-QUERY-05:** The posts page never honors <!--nextpage--> pagination; any page var there produces a 404. 🟢
- **BR-QUERY-06:** An empty author, term or post-type archive returns 200 if the queried object exists; an empty paged archive always 404s. 🟢
- **BR-QUERY-07:** The split-query optimization applies only when no filter altered the SQL and either a persistent object cache exists or posts_per_page < 500. 🟢
- **BR-QUERY-08:** found_posts is computed with SELECT FOUND_ROWS() only when a LIMIT is present and no_found_rows is false. 🟢

## Risks and Gaps

- 🟢 **F-QUERY-01** — WP_Query::get_posts() exposes 34 filters. The generated SQL is a default, not a specification; any statement about what WordPress queries is conditional on the plugin set.
- 🟢 **F-QUERY-02** — The public/private query-var split is the boundary keeping drafts private. It is enforced by two array literals and add_query_var() can breach it in one line.
- 🟢 **F-QUERY-03** — SQL_CALC_FOUND_ROWS is on by default, so every archive page counts the entire matching set to render a pager. The most common WordPress scalability failure.
- 🟢 **F-QUERY-04** — Core search is LIKE '%term%' with a stopword filter: no index usable, no ranking. Any real search requirement needs an external engine.
- 🟢 **F-QUERY-05** — The split-query optimization silently disables itself when any plugin filters the SQL, so adding one filter changes the query shape, not just its clauses.
- 🟢 **F-QUERY-06** — 404 determination happens after the main query has already run, so a 404 page has paid for a full post query.
- 🟢 **F-QUERY-07** — WP_Query is simultaneously a router result, a query builder, an iterator and a state machine for 25+ is_*() conditionals: the most overloaded class in WordPress.
