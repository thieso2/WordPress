## Overview

Turn a URL into a set of posts. WP parses the request into query variables, WP_Query compiles those into SQL, and The Loop iterates the result. WordPress's front controller, router and query layer combined. 🟢

## Responsibilities

- **404 exemption cascade** — Default is to 404. Exemptions for admin/robots/favicon, for found posts with valid pagination, and for empty archives whose queried object exists. Paged empty archives are never exempt 🟢
- **seven-clause SQL assembly with double filtering** — fields, join, where, groupby, orderby, distinct and limits are each filterable early and again as *_request, plus posts_clauses and posts_request over the whole set. 34 filters total 🟢
- **split query** — SELECT ID then hydrate individually from cache, instead of SELECT wp_posts.*. Only for unfiltered queries with either a persistent object cache or posts_per_page < 500 🟢
- **SQL_CALC_FOUND_ROWS pagination** — found_posts read via SELECT FOUND_ROWS(); max_num_pages = ceil(found_posts / posts_per_page). Forces MySQL to count the full match set 🟢
- **stopword-filtered LIKE search** — Terms are trimmed, single a-z/dash tokens and stopwords dropped, survivors become leading-wildcard LIKE conditions. No index usable, no ranking 🟢
- **lazy loop cache priming** — On the first the_post() only, reduce results to ids and bulk-prime post, term, meta and author caches. The loop-level N+1 defense 🟢
