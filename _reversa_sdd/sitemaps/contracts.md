## Contract rules

These rules are **observable by a third party** and therefore part of the contract, not implementation detail. Breaking any of them is a breaking change.

| ID | Rule | Source | Confidence |
|----|------|--------|:----------:|
| `BR-SM-01` | Three built-in providers cover posts, taxonomies and users. | `wp-includes/sitemaps/providers/` | 🟢 |
| `BR-SM-02` | Each sitemap file holds at most 2000 URLs, filterable per object type via wp_sitemaps_max_urls. | `wp-includes/sitemaps.php:90` | 🟢 |
| `BR-SM-03` | An XSL stylesheet is served so the raw XML renders readably in a browser. | `wp-includes/sitemaps/class-wp-sitemaps-stylesheet.php` | 🟢 |
| `BR-SM-04` | Only public post types and public taxonomies are included. | `wp-includes/sitemaps/providers/class-wp-sitemaps-posts.php` | 🟢 |
| `BR-SM-05` | The user provider includes only authors with published posts. | `wp-includes/sitemaps/providers/class-wp-sitemaps-users.php` | 🟢 |

## Risks

- 🟢 **F-SM-01** — A well-factored module (abstract provider, registry, renderer, one tunable) showing what the rest of core would look like if written today.
- 🟡 **F-SM-02** — The 2000-URL page size is 4% of the protocol maximum, a memory-safety choice producing many more files than necessary on large sites.
