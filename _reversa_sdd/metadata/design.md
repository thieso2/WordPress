## Main Flow

1. **string-driven table dispatch** — _get_meta_table() builds '{type}meta' and looks it up as a wpdb property; the object id column is sanitize_key('{type}_id'). Whitelist by property existence.
   Source: `wp-includes/meta.php:1290` 🟢
2. **non-atomic unique check** — SELECT COUNT(*) then INSERT with no unique index on (object_id, meta_key).
   Source: `wp-includes/meta.php:65` 🟢
3. **bulk meta cache priming** — One query with WHERE {column} IN (ids) ORDER BY meta_id ASC, grouped into array<id, array<key, value[]>>. The N+1 defense used by WP_Query.
   Source: `wp-includes/meta.php:1137` 🟢
4. **anti-smuggling protected-key check** — Strips every non-printable-ASCII, non-letter character before testing for a leading underscore, so invisible-character prefixes cannot bypass protection.
   Source: `wp-includes/meta.php:1312` 🟢
5. **three-function default resolution** — get_metadata / get_metadata_raw / get_metadata_default split so registered defaults can be returned without the raw reader knowing about the registry; bridged by filter_default_metadata().
   Source: `wp-includes/meta.php:601` 🟢

## Alternative Flows

- **BR-META-04:** A meta key is protected when its key, stripped of every character that is not printable ASCII or a Unicode letter, begins with underscore. 🟢
- **BR-META-07:** Every meta value passes sanitize_meta(), dispatching to the subtype-specific filter when one is registered. 🟢

## Risks and Gaps

- 🟢 **F-META-01** — Five entity types share one code path parameterized by a string that becomes a SQL table name; a bug here is a bug in every entity type at once.
- 🟢 **F-META-02** — No unique index backs $unique = true. The guarantee is advisory and duplicate meta rows are a known real-world outcome.
- 🟢 **F-META-03** — meta_value is LONGTEXT with no index, so every meta_query is a scan or a meta_key-only join. The root cause of most slow WordPress queries.
- 🟢 **F-META-04** — Whole-object meta caching turns any single-key read into a full meta load: a win in loops, a loss for objects with large meta sets.
- 🟢 **F-META-05** — The underscore-prefix protection is enforced only in UI and REST layers, never at the storage layer. Protected meta is a display convention, not access control.
- 🟡 **F-META-06** — The character-stripping in is_protected_meta() is a deliberate anti-smuggling measure, indicating this check has been attacked before.
