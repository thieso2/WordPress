## Overview

The generic attribute system. One implementation serves posts, comments, terms, users and blogs, driven by a $meta_type string that resolves to a table name. 🟢

**Complexity:** `high` · **Business rules extracted:** 10 · **Public functions catalogued:** 13 · **Extension points:** 15

**Depended on by 9 module(s):** `authentication-and-sessions`, `comments`, `media-and-attachments`, `posts-and-post-types`, `query-and-loop`, `rest-api`, `taxonomy-and-terms`, `users-roles-capabilities`, `widgets-and-nav-menus`

## Responsibilities

- **string-driven table dispatch** — _get_meta_table() builds '{type}meta' and looks it up as a wpdb property; the object id column is sanitize_key('{type}_id'). Whitelist by property existence 🟢
- **non-atomic unique check** — SELECT COUNT(*) then INSERT with no unique index on (object_id, meta_key) 🟢
- **bulk meta cache priming** — One query with WHERE {column} IN (ids) ORDER BY meta_id ASC, grouped into array<id, array<key, value[]>>. The N+1 defense used by WP_Query 🟢
- **anti-smuggling protected-key check** — Strips every non-printable-ASCII, non-letter character before testing for a leading underscore, so invisible-character prefixes cannot bypass protection 🟢
- **three-function default resolution** — get_metadata / get_metadata_raw / get_metadata_default split so registered defaults can be returned without the raw reader knowing about the registry; bridged by filter_default_metadata() 🟢
