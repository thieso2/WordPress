## Overview

Two inverse operations: compile a permalink structure into regex rules mapping URLs to query variables, and generate URLs from objects. WordPress's router. 🟢

**Complexity:** `high` · **Business rules extracted:** 12 · **Public functions catalogued:** 10 · **Extension points:** 15

**Depended on by 5 module(s):** `feeds`, `performance-speculation-view-transitions`, `posts-and-post-types`, `query-and-loop`, `sitemaps`

## Responsibilities

- **positional tag substitution** — Each %tag% is replaced by its regex to build the match pattern and by its query key to build the index.php?... target, using three index-aligned arrays 🟢
- **single-option rule cache** — The complete rule set is serialized into the rewrite_rules option and read on every permalink request; regeneration is triggered when the option is empty 🟢
- **sticky deferred flush** — Flushes before wp_loaded are re-registered on wp_loaded, with a static $do_hard_later accumulating hardness via OR across all deferred callers 🟢
- **verbose page rules** — When a structure starts with a variable tag, an explicit rule is emitted per page so pages can be distinguished from posts, making rule count O(pages) 🟢
