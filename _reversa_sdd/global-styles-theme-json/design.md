## Main Flow

1. **four-origin cascade with early exit** — merge core, then block, then theme, then user data, returning early at the requested origin so callers can obtain pre-user-customization state.
   Source: `wp-includes/class-wp-theme-json-resolver.php:644` 🟢
2. **schema-as-constants** — Valid settings, styles, properties, protected properties, elements and pseudo-selectors are all declared as class constants: a formal data model expressed in PHP arrays.
   Source: `wp-includes/class-wp-theme-json.php` 🟢
3. **viewport breakpoint validation** — is_valid_viewport_breakpoint_size, get_viewport_breakpoint_value_in_pixels and sanitize_viewport_settings validate theme-supplied breakpoints before they become media queries.
   Source: `wp-includes/class-wp-theme-json.php:765` 🟢

## Alternative Flows

- **BR-GS-01:** The four origins merge strictly in order default, blocks, theme, custom; later origins override earlier ones. 🟢

## Internal State

### `WP_Theme_JSON schema constants`

- `VALID_ORIGINS` : `string[4]` — default, blocks, theme, custom
- `VALID_TOP_LEVEL_KEYS` : `string[]`
- `VALID_SETTINGS` : `array schema`
- `VALID_STYLES` : `array schema`
- `PRESETS_METADATA` : `array` — presets become CSS custom properties AND utility classes
- `PROPERTIES_METADATA` : `array` — style path to CSS property mapping
- `PROTECTED_PROPERTIES` : `array` — properties the user origin may not override
- `ELEMENTS` : `array` — link, heading, h1-h6, button, caption, cite
- `ROOT_CSS_PROPERTIES_SELECTOR` : `string` — :root
- `ROOT_BLOCK_SELECTOR` : `string` — body
- `DEFAULT_VIEWPORT_BREAKPOINTS` : `array`

## Risks and Gaps

- 🟢 **F-GS-01** — The only genuinely declarative subsystem in WordPress: everything else is imperative PHP with hooks, while theme.json is data compiled to CSS.
- 🟢 **F-GS-02** — A 216 KB class that is mostly schema constants is effectively a specification written as PHP arrays, the closest thing in core to a formal data model.
- 🟢 **F-GS-03** — The four-origin cascade with early exit lets every consumer ask 'what would this be without user edits?', which makes non-destructive reset possible.
- 🟡 **F-GS-04** — Storing user styles as a post per theme means switching themes silently switches style sets, and wp_global_styles posts accumulate for uninstalled themes.
- 🟢 **F-GS-05** — theme.json is theme-supplied data that becomes CSS media queries, so the viewport validation chain is a real injection boundary rather than schema tidiness.
