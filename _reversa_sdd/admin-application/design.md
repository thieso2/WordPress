## Main Flow

1. **shared bootstrap gate** — admin.php defines the admin context constants, loads WordPress, requires the admin includes, and calls auth_redirect() once before firing admin_init, so every screen inherits authentication.
   Source: `wp-admin/admin.php` 🟢
2. **action-name ajax dispatch** — $_REQUEST['action'] selects wp_ajax_{action} for logged-in users or wp_ajax_nopriv_{action} for anonymous ones; the nopriv variant IS the authorization model.
   Source: `wp-admin/admin-ajax.php` 🟢

## Dependencies

- `authentication-and-sessions` — Prove identity and maintain it across requests: password hashing, cookie-based sessions, session tokens, nonces, and the pluggable-function override mechanism 🟢
- `users-roles-capabilities` — The authorization model 🟢
- `bootstrap-and-load` — Turn a bare PHP request into a fully initialized WordPress runtime: locate configuration, verify host requirements, define constants, connect the database, start the object cache, load plugins and the theme, hand off to the request handler 🟢
- `cron` — Schedule deferred and recurring work 🟢
- `options-and-transients` — WordPress's key-value store 🟢
- `hooks-plugin-api` — The extension mechanism the entire system is built on 🟢
- `filesystem-api` — Write files portably, including on hosts where PHP cannot write directly and must go through FTP or SSH; plus Ed25519 verification of update packages 🟢
- `updates-and-upgrader` — Check for, download, verify and install core, plugin, theme and translation updates, and migrate the database schema between versions 🟢

**Depended on by:** `multisite`, `site-health`

## Risks and Gaps

- 🟢 **F-ADM-01** — Admin-Ajax has no declarative authorization; compared to REST's permission_callback, every ajax action must remember its own capability and nonce check. The most common source of WordPress privilege-escalation CVEs.
- 🟢 **F-ADM-02** — One screen per file with 95 files and no controller layer means routing is the filesystem, so there is no central place to enforce a policy across admin screens.
- 🟢 **F-ADM-03** — WP_List_Table is officially private and universally extended; documentation and reality diverge completely.
- 🟡 **F-ADM-04** — The admin re-schedules missing cron events on load, quietly repairing a broken cron option, but only if an administrator visits.
