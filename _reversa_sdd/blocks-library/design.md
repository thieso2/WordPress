## Alternative Flows

- **BR-BLIB-04:** The 'missing' block preserves the original content when a block type is not registered. It is a STATIC block — wp-includes/blocks/missing/ contains only block.json; the placeholder is rendered client-side by the editor, not by PHP. 🟢
- **BR-BLIB-05:** The 'freeform' block wraps pre-block classic editor content. It is a STATIC block — wp-includes/blocks/freeform/ contains block.json and editor CSS only. The wrapping happens in blocks.php, not in a render callback. 🟢

## Risks and Gaps

- 🟢 **F-BLIB-01** — A 206 KB generated PHP array is loaded to avoid 115 file reads; core traded memory on every request against I/O on every request.
- 🟢 **F-BLIB-02** — 88 of 115 core blocks (76.5%) are dynamic, counted from require-dynamic-blocks.php. The block system stores markup for only 27 blocks; for the rest, output is computed at render time.
- 🟢 **F-BLIB-03** — The missing block is a graceful-degradation mechanism preserving content when a block-providing plugin is deactivated, the block equivalent of _menu_item_orphaned.
- 🟢 **F-BLIB-04** — Blocks now cover comments, queries, navigation and site identity, functionality previously owned by templates, widgets and menus: four systems expressing the same capabilities.
