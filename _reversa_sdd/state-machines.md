## 1. Post status

**The most important state machine in WordPress**, and an unusual one: the state is *computed*, not
assigned (BR-POST-01/02).

### States 🟢

| Status | Meaning | Public? |
|--------|---------|---------|
| `auto-draft` | Row created before the user typed anything. Garbage-collected after 7 days. | ❌ |
| `draft` | Unpublished work in progress. No slug generated. | ❌ |
| `pending` | Awaiting editorial review. No slug generated. | ❌ |
| `future` | Scheduled. A `publish_future_post` cron event is pending. | ❌ |
| `publish` | Live. | ✅ |
| `private` | Live but visible only to users with `read_private_posts`. | ❌ |
| `trash` | Soft-deleted; original status preserved in `_wp_trash_meta_status`. | ❌ |
| `inherit` | Attachments and revisions — the effective status is the parent's. | — |
| `request-pending` / `request-confirmed` / `request-failed` | GDPR `user_request` posts only. | ❌ |

### Transitions 🟢

```mermaid
stateDiagram-v2
    [*] --> auto_draft : new post screen opened

    auto_draft --> draft : first save
    auto_draft --> [*] : 7-day cleanup (wp_delete_auto_drafts)

    draft --> pending : submit for review
    draft --> publish : publish, date <= now + 60s
    draft --> future : publish, date > now + 60s
    draft --> private : publish as private
    draft --> trash : trash

    pending --> draft : return to draft
    pending --> publish : approve, date <= now + 60s
    pending --> future : approve, date > now + 60s
    pending --> trash : trash

    future --> publish : publish_future_post cron fires
    future --> draft : unschedule (cron event CLEARED)
    future --> trash : trash

    publish --> draft : unpublish
    publish --> private : make private
    publish --> trash : trash

    private --> publish : make public
    private --> draft : unpublish
    private --> trash : trash

    trash --> draft : untrash (restores _wp_trash_meta_status)
    trash --> pending : untrash
    trash --> publish : untrash
    trash --> private : untrash
    trash --> [*] : EMPTY_TRASH_DAYS elapsed, or force_delete

    note right of future
        BR-POST-02: entering 'future' with a
        date less than 60s away is silently
        converted to 'publish'.
    end note

    note right of trash
        Every transition into or out of trash
        clears publish_future_post (BR-POST-11):
        "in case the post status bounced
         from future to draft"
    end note
```

### The 60-second rule 🟢

The `draft → publish` and `draft → future` edges are **not chosen by the caller**. `wp_insert_post()`
computes them:

```
publish requested, post_date_gmt - now >= 60s   → status becomes 'future'
future  requested, post_date_gmt - now <  60s   → status becomes 'publish'
```

### Side effects on every transition 🟢

`wp_transition_post_status()` fires `transition_post_status` **and** the dynamic
`{$old}_to_{$new}` action — 11 statuses generate up to **121 undeclared hook names** (F-POST-04).

`_transition_post_status()` then:

1. Seeds `guid` from `get_permalink()` on first entry to `publish` — once, never again.
2. Invalidates `lastpostmodified` / `lastpostdate` for `server`, `gmt` and `blog` timezones.
3. Invalidates post-count caches.
4. **Unconditionally** clears `publish_future_post`.

## 2. Comment approval

### States 🟢

`comment_approved` is a **varchar**, not a boolean (BR-CMT-12):

| Value | Meaning |
|-------|---------|
| `'1'` | Approved and displayed |
| `'0'` | Held for moderation |
| `'spam'` | Marked as spam |
| `'trash'` | Soft-deleted |
| `'post-trashed'` | The parent post was trashed; restored when the post is untrashed |

### The approval decision 🟢

```mermaid
stateDiagram-v2
    [*] --> Submitted : wp_handle_comment_submission()

    Submitted --> Rejected409 : duplicate detected (BR-CMT-01)
    Submitted --> Rejected429 : flood filter returns true (BR-CMT-04)
    Submitted --> Evaluating : passes both gates

    state Evaluating {
        [*] --> AuthorCheck
        AuthorCheck --> Approved1 : is post author OR has moderate_comments
        AuthorCheck --> Moderation : everyone else

        state Moderation {
            [*] --> ManualGate
            ManualGate --> Held : comment_moderation == '1'
            ManualGate --> LinkGate : otherwise
            LinkGate --> Held : link count >= comment_max_links
            LinkGate --> KeywordGate : otherwise
            KeywordGate --> Held : moderation_keys substring match
            KeywordGate --> PriorGate : otherwise
            PriorGate --> Held : comment_previously_approved and no prior approval
            PriorGate --> Approved : otherwise
        }

        Moderation --> DisallowedCheck
        Approved1 --> DisallowedCheck
    }

    DisallowedCheck --> Trash : disallowed match AND EMPTY_TRASH_DAYS
    DisallowedCheck --> Spam : disallowed match AND NOT EMPTY_TRASH_DAYS
    DisallowedCheck --> FinalFilter : no disallowed match

    FinalFilter --> Stored : pre_comment_approved filter

    Stored --> Approved_1 : '1'
    Stored --> Held_0 : '0'
    Stored --> Spam
    Stored --> Trash

    Approved_1 --> Held_0 : unapprove
    Approved_1 --> Spam : mark as spam
    Approved_1 --> Trash : trash
    Held_0 --> Approved_1 : approve
    Held_0 --> Spam : mark as spam
    Held_0 --> Trash : trash
    Spam --> Approved_1 : not spam
    Spam --> Held_0 : not spam
    Trash --> Approved_1 : untrash
    Trash --> Held_0 : untrash
    Trash --> [*] : permanently delete

    Approved_1 --> PostTrashed : parent post trashed
    Held_0 --> PostTrashed : parent post trashed
    PostTrashed --> Approved_1 : parent post untrashed
    PostTrashed --> Held_0 : parent post untrashed

    note right of DisallowedCheck
        The disallowed list runs AFTER the
        approval decision and OVERRIDES it
        (BR-CMT-10). Whether the result is
        'trash' or 'spam' depends on an
        unrelated constant.
    end note
```

**Note the ordering:** the author/moderator exemption (BR-CMT-05) skips all four moderation rules but
**not** the disallowed-list check. An administrator's comment containing a disallowed word is still
trashed.

## 3. Plugin lifecycle

### States 🟢

```mermaid
stateDiagram-v2
    [*] --> NotInstalled

    NotInstalled --> Installed : upload / install from directory
    Installed --> Active : activate → fires activate_{plugin_file}
    Active --> Installed : deactivate → fires deactivate_{plugin_file}
    Installed --> NotInstalled : delete → runs uninstall_plugins callback or uninstall.php

    Active --> Paused : FATAL ERROR caught by WP_Fatal_Error_Handler
    Paused --> Active : administrator exits recovery mode
    Paused --> Installed : deactivated while paused

    Active --> NetworkActive : network activate (multisite)
    NetworkActive --> Active : network deactivate

    note right of Paused
        BR-BOOT-05: a paused plugin is
        SKIPPED at boot on every subsequent
        request until recovery mode is exited.
        The site loads without it rather
        than fataling again.
    end note

    note right of NotInstalled
        BR-HOOK-09: the uninstall callback is
        SERIALIZED into the uninstall_plugins
        option, which is why instance methods
        are rejected.
    end note
```

**Load order at boot** (BR-BOOT-06 and `wp-settings.php`):

```
mu-plugins → network plugins → [muplugins_loaded] → active plugins
→ pluggable.php → [plugins_loaded]
```

`pluggable.php` loading *after* active plugins is what makes the 35 security functions replaceable.

## 4. Recovery mode

```mermaid
stateDiagram-v2
    [*] --> Normal

    Normal --> FatalCaught : E_ERROR / E_PARSE / E_USER_ERROR /<br/>E_COMPILE_ERROR / E_RECOVERABLE_ERROR

    FatalCaught --> Attributed : get_extension_for_error()<br/>maps file path → plugin or theme
    FatalCaught --> Unattributed : path matches no extension

    Attributed --> Paused : store_error() writes to<br/>paused-extensions storage
    Paused --> EmailSent : recovery email with signed link<br/>(rate-limited to 1/day)
    Paused --> EmailSuppressed : within the rate-limit window

    EmailSent --> RecoveryActive : admin follows the link<br/>(TTL >= rate limit, BR-ERR-08)
    RecoveryActive --> Normal : exit_recovery_mode()<br/>clears paused extensions + cookie

    Unattributed --> ErrorTemplate : white-screen replacement<br/>or fatal-error-handler.php drop-in

    note right of Paused
        The site now loads WITHOUT the
        paused extension. Visitors see a
        working, degraded site rather than
        a fatal error.
    end note

    note right of EmailSent
        BR-ERR-08: link TTL is
        max(filtered_ttl, rate_limit),
        so a link can never expire before
        a replacement may be sent.
    end note
```

## 5. Update lifecycle

```mermaid
stateDiagram-v2
    [*] --> Current

    Current --> CheckScheduled : wp_version_check / wp_update_plugins / wp_update_themes
    CheckScheduled --> Current : within 12h of last_checked (BR-UPD-03)
    CheckScheduled --> Checking : timeout elapsed

    Checking --> Current : no update available
    Checking --> UpdateAvailable : response cached in site transient
    Checking --> BackedOff : request failed → timeout escalates<br/>1min → 1h → 2h → 12h

    BackedOff --> CheckScheduled

    UpdateAvailable --> Downloading : manual or auto-update
    Downloading --> Verifying : download_url()
    Verifying --> Failed : signature invalid
    Verifying --> Unsupported : no sodium / no sha384 (BR-FS-07)
    Verifying --> Verified : Ed25519 signature valid

    Unsupported --> Unpacking : proceeds UNVERIFIED
    Verified --> Unpacking

    Unpacking --> Installing : ZipArchive or PclZip
    Installing --> Maintenance : .maintenance written
    Maintenance --> Installed : files copied, obsolete files removed
    Installed --> Current : maintenance cleared

    Installing --> Paused : fatal on load after update
    Paused --> Current : recovery mode exit

    note right of Unsupported
        Availability over integrity:
        a host without sodium installs
        the update without verifying it.
    end note

    note right of Maintenance
        BR-BOOT-02: a .maintenance file
        older than 10 minutes is IGNORED,
        so a crashed update cannot
        permanently lock the site.
    end note
```

## 6. Multisite site status

```mermaid
stateDiagram-v2
    [*] --> Signup : wp-signup.php → wp_signups row
    Signup --> Activated : activation key used (wp-activate.php)
    Signup --> [*] : signup expires

    Activated --> Public : public = 1
    Public --> Private : public = 0
    Private --> Public : public = 1

    Public --> Archived : archived = 1
    Private --> Archived : archived = 1
    Archived --> Public : archived = 0

    Public --> Spam : spam = 1
    Spam --> Public : spam = 0

    Public --> Mature : mature = 1
    Mature --> Public : mature = 0

    Public --> Deleted : deleted = 1
    Archived --> Deleted : deleted = 1
    Spam --> Deleted : deleted = 1
    Deleted --> Public : deleted = 0
    Deleted --> [*] : wp_delete_site() drops the tables

    note right of Deleted
        'deleted' is a FLAG, not a deletion.
        The tables remain until
        wp_delete_site() runs.
    end note
```

`wp_blogs` carries five independent boolean flags — `public`, `archived`, `mature`, `spam`,
`deleted` — so a site's "state" is a **combination**, not a single value. 🟢

## 7. Findings

| # | Finding | Confidence |
|---|---------|-----------|
| F-SM-01 | Post status is the only state machine in WordPress where the *machine itself* decides the state from a data value rather than from the requested transition. | 🟢 |
| F-SM-02 | The `{$old}_to_{$new}` dynamic hook means 121 transition hooks exist that no static analysis can enumerate — they are generated from the status registry at runtime. | 🟢 |
| F-SM-03 | Comment approval has two sequential decision layers (moderation, then disallowed list) where the second overrides the first. The author/moderator exemption bypasses only the first. | 🟢 |
| F-SM-04 | Multisite site state is five independent flags, not an enum, so 32 combinations are representable and only a handful are meaningful. | 🟡 |
| F-SM-05 | Every failure path in the update and recovery machines has a self-healing escape (stale maintenance file, rate-limit-bounded link TTL, paused-extension skip), which is why WordPress rarely stays broken. | 🟢 |
