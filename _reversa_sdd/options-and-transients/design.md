## Main Flow

1. **five-level option read cascade** — pre_option filters -> alloptions bulk cache -> notoptions negative cache -> per-option object cache -> single-row SELECT. Misses are recorded in notoptions so they never re-query.
   Source: `wp-includes/option.php:78` 🟢
2. **automatic autoload sizing** — Serialized values over 150000 bytes are demoted to auto-off, protecting every request from a single oversized autoloaded option.
   Source: `wp-includes/option.php:1353` 🟢
3. **two-row transient with lazy expiry** — Value and timeout stored as separate option rows; expiry checked on read, both rows deleted when stale. Repairs a missing timeout row by recreating both.
   Source: `wp-includes/option.php:1431` 🟢
4. **autoload-as-expiry-proxy** — get_transient() uses presence in alloptions to infer the transient has no timeout, avoiding a timeout lookup. Couples the autoload flag to transient semantics.
   Source: `wp-includes/option.php:1441` 🟢

## Alternative Flows

- **BR-OPT-04:** update_option() returns false when the value is unchanged, making 'no change' indistinguishable from 'failure'. 🟢
- **BR-OPT-07:** An explicit on/off autoload value is never overridden by the automatic heuristic; only auto, auto-on and auto-off are re-evaluated. 🟢
- **BR-OPT-10:** With a persistent object cache present, transients never touch the database. 🟢
- **BR-OPT-14:** The wp_autoload_values_to_autoload filter can only remove values from the valid set, never add new ones (array_intersect guard). 🟢

## Risks and Gaps

- 🟢 **F-OPT-01** — wp_options is the most contended table in WordPress: configuration, plugin settings, transient cache and expiry timestamps share one key-value table with one unique index.
- 🟢 **F-OPT-02** — autoload as a 6-valued enum rather than a boolean preserves the distinction between human decision and heuristic, so the heuristic never overrides intent.
- 🟢 **F-OPT-03** — update_option() returning false for 'unchanged' is a persistent source of caller bugs with no way to distinguish it from a write failure.
- 🟢 **F-OPT-04** — Transients silently change storage backend based on the presence of a persistent object cache: a real testing hazard between production and default installs.
- 🟢 **F-OPT-05** — Transient expiry has no guaranteed upper bound; without read traffic or the cron sweep, expired rows persist indefinitely.
- 🟡 **F-OPT-06** — The 150KB autoload-size heuristic is a mitigation, not a fix: hundreds of options just under the limit still bloat every request.
- 🟢 **F-OPT-07** — pre_option_{option} allows a plugin to fully replace any option read without touching the database, making any option's value unspecifiable in isolation.
