## Main Flow

1. **context-specific output escaping** — A distinct escaper per output context (HTML text, attribute, URL-in-markup, raw URL, JS, textarea, XML), applied at render rather than at storage.
   Source: `wp-includes/formatting.php` 🟢
2. **regex typographic transformation** — wpautop and wptexturize transform rendered HTML with regular expressions while maintaining skip-lists for block-level and code tags.
   Source: `wp-includes/formatting.php` 🟢

## Alternative Flows

## Identified Design Decisions

| Decision | Evidence in the code | Confidence |
|----------|----------------------|------------|
| A distinct escaper per output context (HTML text, attribute, URL-in-markup, raw URL, JS, textarea, XML), applied at render rather than at storage | `wp-includes/formatting.php` | 🟢 |
| wpautop and wptexturize transform rendered HTML with regular expressions while maintaining skip-lists for block-level and code tags | `wp-includes/formatting.php` | 🟢 |
| Escaping is applied at output and chosen by context; there is no single universal escaper | `wp-includes/formatting.php` | 🟢 |
| esc_url() encodes & to &amp; for use in markup; esc_url_raw() does not, for storage and Location headers | `wp-includes/formatting.php` | 🟢 |
| wpautop() and wptexturize() run on the_content output, not on stored content, which is why the database holds plain newlines | `wp-includes/default-filters.php` | 🟢 |
| Both wpautop() and wptexturize() skip a maintained list of block-level and code tags | `wp-includes/formatting.php` | 🟢 |
| All superglobal input is slashed by wp_magic_quotes(); wp_unslash() is required before use | `wp-includes/load.php:1285` | 🟢 |
| sanitize_title() produces a URL-safe slug; sanitize_key() lowercases and restricts to [a-z0-9_-] | `wp-includes/formatting.php` | 🟢 |

## Risks and Gaps

- 🟢 **F-FMT-01** — A 350 KB file mixing escaping, sanitizing, typography and slashing is the largest single grab-bag in core and is loaded on every request.
- 🟢 **F-FMT-02** — The escape-at-output discipline is WordPress's primary XSS defense but is a convention enforced by review, not by the type system or the API.
- 🟢 **F-FMT-03** — esc_url() and esc_url_raw() differ by one character of output and are used in different contexts; the naming does not signal which is which.
- 🟢 **F-FMT-04** — Regex-based HTML transformation in wpautop and wptexturize is exactly what the HTML API replaced elsewhere, yet both still run on every rendered post.
- 🟢 **F-FMT-05** — The universal slashing convention has no compile-time or runtime enforcement; a missing wp_unslash() produces visible corruption rather than an error.
