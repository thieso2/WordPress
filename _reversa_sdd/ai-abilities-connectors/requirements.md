## Overview

The newest subsystem: a registry of typed, permission-gated, schema-described abilities that AI agents can discover and invoke, plus a provider-agnostic AI client. 🟢

**Complexity:** `high` · **Business rules extracted:** 10 · **Public functions catalogued:** 8 · **Extension points:** 3

**Depended on by 0 module(s):** _none — terminal module_

## Responsibilities

- **five-stage ability execution** — normalize_input, validate_input against JSON Schema, check_permissions, do_execute, then validate_output against JSON Schema. Output validation is unique in core 🟢
- **strict registration** — Mandatory namespace pattern, no overwrite of an existing name, and a category that must already exist; all three fail with _doing_it_wrong() and a null return 🟢
- **ability to AI function bridge** — The ability-function resolver turns a registered ability's schemas into an LLM tool definition, so one declaration becomes both a REST endpoint and a model-callable function 🟢
