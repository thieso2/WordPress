## Overview

The entire data access layer. A single ~4230-line class with no ORM, no query builder and no server-side prepared statements. Every module reaches the database through the global $wpdb. 🟢

**Complexity:** `high` · **Business rules extracted:** 14 · **Public functions catalogued:** 18 · **Extension points:** 1

**Depended on by 11 module(s):** `bootstrap-and-load`, `comments`, `metadata`, `multisite`, `options-and-transients`, `posts-and-post-types`, `query-and-loop`, `site-health`, `taxonomy-and-terms`, `updates-and-upgrader`, `users-roles-capabilities`

## Responsibilities

- **prepare() placeholder interpolation** — sprintf-derived: strips caller quotes, escapes stray percents, preg_split with stride 3, classifies %s/%d/%f/%F/%i, checks identifier-vs-value conflicts and arity, then escapes and interpolates 🟢
- **placeholder escape sentinel** — Per-request hash_hmac sentinel replaces literal % in values; a query filter at priority 0 restores it just before execution, blocking second-order placeholder injection 🟢
- **charset upgrade cascade** — utf8 -> utf8mb4; utf8_general_ci -> utf8mb4_unicode_ci; -> utf8mb4_unicode_520_ci when the server supports it 🟢
- **invalid text rejection** — Per-column charset and byte length are read via SHOW FULL COLUMNS and memoized; unrepresentable writes are refused rather than mangled. check_ascii() is the fast path 🟢
- **reconnect with backoff** — DO 1 liveness probe, then 5 retries with sleep(1); silent failure after template_redirect 🟢
