## Main Flow

1. **four-level registry** — Panel contains Section contains Control which writes Setting; controls are UI and settings are storage, in a many-to-many relationship.
   Source: `wp-includes/class-wp-customize-manager.php:3786` 🟢
2. **changeset as a post** — Unsaved state is serialized into a customize_changeset post keyed by UUID rather than a session, enabling shareable preview links and scheduled publication.
   Source: `wp-includes/class-wp-customize-manager.php:2642` 🟢
3. **three-stage value pipeline** — validate_callback rejects, sanitize_callback cleans for storage, sanitize_js_callback prepares for the JS preview.
   Source: `wp-includes/class-wp-customize-setting.php:92` 🟢

## Risks and Gaps

- 🟢 **F-CUST-01** — Per-setting capabilities make the Customizer the most granular authorization surface in WordPress, finer than the admin screens it configures.
- 🟢 **F-CUST-02** — Storing unsaved state as a post makes previews shareable and schedulable at the cost of customize_changeset rows accumulating in wp_posts.
- 🟢 **F-CUST-03** — A 198 KB manager class with a roughly 1000-line register_controls() is the second-largest single unit of coupling after post.php.
- 🟢 **F-CUST-04** — The Customizer, widgets and nav menus are three overlapping settings surfaces that the block editor partially replaces without removing any of them; core carries all four.
