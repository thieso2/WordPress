## 1. Simplified overall ERD 🟢

```mermaid
erDiagram
    users ||--o{ posts : authors
    users ||--o{ comments : writes
    posts ||--o{ comments : receives
    posts }o--o{ term_taxonomy : "classified by (via term_relationships)"
    terms ||--o{ term_taxonomy : "is a"
    posts ||--o{ posts : "parents (3 meanings)"

    users { bigint ID PK }
    posts { bigint ID PK "16 post types in ONE table" }
    comments { bigint comment_ID PK }
    terms { bigint term_id PK "the word" }
    term_taxonomy { bigint term_taxonomy_id PK "the classification" }
```

Four meta tables (`postmeta`, `commentmeta`, `termmeta`, `usermeta`) hang off the four entities and
are omitted here for legibility — see §2.3.

## 2. Domain partitions

### 2.1 Content 🟢

```mermaid
erDiagram
    posts ||--o{ postmeta : "post_id"
    posts ||--o{ posts : "post_parent"
    users ||--o{ posts : "post_author"

    posts {
        bigint ID PK
        bigint post_author FK
        datetime post_date_gmt "0000-00-00 for drafts"
        varchar post_status "11 values, DERIVED from date"
        varchar post_name "slug, 3 uniqueness scopes"
        bigint post_parent FK "page | revision | attachment"
        varchar guid "seeded once from permalink"
        varchar post_type "16 built-in"
        bigint comment_count "denormalised counter"
    }
    postmeta {
        bigint meta_id PK
        bigint post_id FK
        varchar meta_key "indexed to 191 bytes"
        longtext meta_value "NO INDEX"
    }
```

### 2.2 Classification 🟢

```mermaid
erDiagram
    terms ||--o{ term_taxonomy : "term_id"
    terms ||--o{ termmeta : "term_id"
    term_taxonomy ||--o{ term_relationships : "term_taxonomy_id"
    term_taxonomy ||--o{ term_taxonomy : "parent (cycle-guarded in PHP)"
    posts ||--o{ term_relationships : "object_id"

    terms { bigint term_id PK  varchar name  varchar slug  bigint term_group }
    term_taxonomy { bigint term_taxonomy_id PK  bigint term_id FK  varchar taxonomy  bigint parent  bigint count "DIRECT only" }
    term_relationships { bigint object_id PK_FK  bigint term_taxonomy_id PK_FK  int term_order }
```

### 2.3 Metadata — one shape, five tables 🟢

```mermaid
erDiagram
    postmeta    { bigint meta_id PK   bigint post_id FK    varchar meta_key  longtext meta_value }
    commentmeta { bigint meta_id PK   bigint comment_id FK varchar meta_key  longtext meta_value }
    termmeta    { bigint meta_id PK   bigint term_id FK    varchar meta_key  longtext meta_value }
    usermeta    { bigint umeta_id PK  bigint user_id FK    varchar meta_key  longtext meta_value }
    blogmeta    { bigint meta_id PK   bigint blog_id FK    varchar meta_key  longtext meta_value }
```

🟢 Identical but for `usermeta`'s `umeta_id`. All five are served by one code path in `meta.php`
(F-META-01).

### 2.4 Identity and access 🟢

```mermaid
erDiagram
    users ||--o{ usermeta : "user_id"
    users {
        bigint ID PK
        varchar user_login "indexed, NOT unique-constrained"
        varchar user_pass "$P$ | $2y$ | $wp$2y$"
        varchar user_email
        varchar user_activation_key
        int user_status
    }
    usermeta {
        bigint umeta_id PK
        bigint user_id FK
        varchar meta_key "wp_capabilities = THE ROLE STORE"
        longtext meta_value "serialized role map"
    }
```

⚠️ 🟢 **There is no role table.** Authorization is a serialized array in a `usermeta` row.

### 2.5 Configuration 🟢

```mermaid
erDiagram
    options {
        bigint option_id PK
        varchar option_name UK "the only load-bearing unique constraint"
        longtext option_value
        varchar autoload "6-valued enum, INDEXED"
    }
```

🟢 This one table holds site configuration, plugin settings, **the entire rewrite rule set**, **the
entire cron queue**, and the transient cache (F-OPT-01, F-RW-02, F-CRON-03).

### 2.6 Multisite 🟢

```mermaid
erDiagram
    site ||--o{ blogs : "site_id"
    site ||--o{ sitemeta : "site_id"
    blogs ||--o{ blogmeta : "blog_id"
    signups }o..o{ blogs : "activation creates"

    site { bigint id PK  varchar domain  varchar path }
    blogs {
        bigint blog_id PK
        bigint site_id FK
        varchar domain
        varchar path
        tinyint public
        tinyint archived
        tinyint mature
        tinyint spam
        tinyint deleted "a FLAG, not a deletion"
    }
    signups { bigint signup_id PK  varchar activation_key  tinyint active }
    sitemeta { bigint meta_id PK  bigint site_id FK  varchar meta_key  longtext meta_value }
```

🟢 Five independent boolean flags rather than a status enum — 32 representable states, a handful
meaningful (F-ERD-06).

## 3. What no diagram can show 🟢

| Relationship | Why it is invisible |
|--------------|--------------------|
| Site → its content | Encoded in the **table name prefix**, not a column |
| User → role on a site | Encoded in a **meta key name**, `wp_{prefix}capabilities` |
| Menu item → its target | Nine `_menu_item_*` meta rows, not columns (BR-MENU-02) |
| Attachment → its file | `_wp_attached_file` meta pointing at the filesystem |
| Any of the above → integrity | **Nothing.** No foreign key exists anywhere (F-DD-01) |
