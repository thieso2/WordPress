## What replaces them

| Where another system would use… | WordPress uses… |
|--------------------------------|-----------------|
| A trigger to maintain a count | `wp_update_term_count()` / `wp_update_comment_count()`, both deferrable in PHP (BR-TAX-09, BR-CMT-13) |
| A trigger for cascade delete | Explicit deletion in `wp_delete_post()`, `wp_delete_term()`, `wp_delete_user()` |
| A view for a common join | `WP_Query`'s clause builder, with 34 filters (F-QUERY-01) |
| A stored procedure for a transaction | Compensating logic — there are no transactions (F-DB-06) |
| A scheduled event | WP-Cron, drained by visitor traffic (ADR-006) |
| A computed column | Computed at read time, e.g. `_pad_term_counts()` for hierarchical counts (BR-TAX-11) |

## Consequence

🟢 **The database is fully portable and fully passive.** WordPress can run on MySQL, MariaDB or
Percona with no server-side objects to install, migrate or version — but every rule must be
re-executed by the application on every operation, and any write that bypasses PHP bypasses every
rule.
