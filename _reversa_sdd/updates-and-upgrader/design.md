## Main Flow

1. **escalating check backoff** — Timeout rises from 1 minute during cron through 1 hour and 2 hours to 12 hours in steady state, so a failing update endpoint costs one slow request per hour rather than one per page view.
   Source: `wp-includes/update.php:383` 🟢
2. **diff-based schema migration** — dbDelta() compares wp_get_db_schema()'s CREATE TABLE statements with the live schema and emits ALTER statements; data migrations that cannot be expressed as schema shape live in version-gated upgrade_NNN() functions.
   Source: `wp-admin/includes/upgrade.php` 🟢
3. **download-verify-unpack-install pipeline** — download_package with signature verification, unpack via ZipArchive or PclZip, install_package under maintenance mode, with per-version file manifests for core cleanup.
   Source: `wp-admin/includes/class-wp-upgrader.php` 🟢

## Risks and Gaps

- 🟢 **F-UPD-01** — The escalating timeout is a well-judged backoff: a failing update endpoint costs a site one slow request per hour rather than one per page view.
- 🟢 **F-UPD-02** — dbDelta() infers migrations by diffing rather than recording them; it cannot express data migrations, only schema shape, which is why upgrade_NNN() functions exist alongside it.
- 🟢 **F-UPD-03** — Auto-updates plus maintenance mode plus paused extensions plus recovery mode compose into a resilient update story, each mechanism covering a different failure mode of the others.
- 🟢 **F-UPD-04** — Core knows the file manifest of every prior version in order to clean up, and that list is hand-maintained in update-core.php.
