## Main Flow

1. **table-prefix site isolation** — Blog-scoped tables are prefixed per blog id while users, usermeta and the ms-global tables are shared; set_blog_id() recomputes only the blog-scoped names.
   Source: `wp-includes/class-wpdb.php:1043` 🟢
2. **stacked blog switching** — switch_to_blog pushes onto a stack and updates wpdb prefix, object cache blog prefix and assorted globals; restore_current_blog pops. An unbalanced switch corrupts every subsequent query.
   Source: `wp-includes/ms-blogs.php` 🟢

## Observability

- BR-MS-01 — Each site gets its own prefixed table set (wp_{blog_id}_posts etc.); users and usermeta are shared network-wide. `wp-includes/class-wpdb.php:291`
- BR-MS-02 — switch_to_blog() maintains a stack and must be paired with restore_current_blog(). `wp-includes/ms-blogs.php`
- BR-MS-03 — Switching a blog changes $wpdb's table prefix and the object cache's blog prefix together. `wp-includes/class-wpdb.php:1043`
- BR-MS-08 — Site and network options live in wp_blogmeta and wp_sitemeta respectively. `wp-includes/option.php:2001`

## Risks and Gaps

- 🟢 **F-MS-01** — Table-per-site means a 1000-site network has roughly 11000 tables; schema migrations must run per site and dbDelta() is invoked once per blog.
- 🟢 **F-MS-02** — switch_to_blog() changes global state and must be unwound manually; an unbalanced switch corrupts every subsequent query in the request.
- 🟢 **F-MS-03** — Multisite is not a layer on top of WordPress but is_multisite() branches threaded through the kernel: wpdb, the object cache, capabilities, options and boot all behave differently.
- 🟡 **F-MS-04** — Shared users with per-site roles is the right model but means user meta grows linearly with the number of sites a user belongs to.
