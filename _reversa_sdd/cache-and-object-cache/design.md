## Main Flow

1. **multisite key prefixing** — Non-global-group keys get '{blog_id}:' prepended. The entire multisite cache isolation mechanism is a string prefix.
   Source: `wp-includes/class-wp-object-cache.php:311` 🟢
2. **null-safe existence check** — isset() OR array_key_exists() so a cached null is a hit, not a miss.
   Source: `wp-includes/class-wp-object-cache.php:178` 🟢
3. **double clone isolation** — Objects cloned on both set and get so caller mutation cannot corrupt the in-process cache array.
   Source: `wp-includes/class-wp-object-cache.php:314` 🟢

## Alternative Flows

- **BR-CACHE-01:** The default object cache is request-scoped only; nothing survives the response. 🟢
- **BR-CACHE-06:** $expire is accepted and ignored by the default implementation. 🟢
- **BR-CACHE-08:** An empty $group becomes 'default'. 🟢
- **BR-CACHE-10:** get() sets the by-reference $found parameter, the only reliable way to distinguish a cached false from a miss. 🟢

## Risks and Gaps

- 🟢 **F-CACHE-01** — The default cache being non-persistent means most WordPress installs run with no real caching; performance observed on a default install does not transfer to one with Redis or Memcached.
- 🟢 **F-CACHE-02** — The object-cache.php drop-in is an implicit interface with no formal contract; cache-compat.php exists to polyfill drop-ins predating newer methods.
- 🟢 **F-CACHE-03** — Cache correctness for false and null depends on callers using $found; callers checking 'if (false === $value)' re-query on every legitimately-false cached value.
- 🟢 **F-CACHE-04** — Multisite cache isolation is a string prefix, so a drop-in ignoring switch_to_blog() leaks data across sites.
- 🟡 **F-CACHE-05** — Double-cloning every cached object is measurable overhead in object-heavy paths, paid because the cache is a live in-process array.
