## Overview

Parse, register and render the block-based content format. Post content is HTML with block boundaries encoded as HTML comments; this module turns that string into a tree and back. 🟢

**Complexity:** `high` · **Business rules extracted:** 12 · **Public functions catalogued:** 13 · **Extension points:** 11

**Depended on by 5 module(s):** `block-supports`, `blocks-library`, `global-styles-theme-json`, `interactivity-api`, `themes-and-templates`

## Responsibilities

- **comment-delimited format** — Structure encoded as HTML comments so content degrades gracefully; namespace optional and defaulting to core/; open/close, void and freeform forms 🟢
- **possessive-quantifier JSON brace matcher** — The attrs sub-pattern uses *+ with two lookaheads to match a JSON object containing } characters, stopping at the } preceding the comment terminator, without catastrophic backtracking 🟢
- **stack-machine parsing with implicit recovery** — proceed() dispatches on token type; no-more-tokens with a non-empty stack closes every open block implicitly, so parsing never fails 🟢
- **null-placeholder serialization** — innerContent records the block's own HTML as strings and its children's positions as nulls; serialize_block walks the array substituting each null with the next serialized inner block, giving lossless round-tripping 🟢
- **three-source metadata resolution** — Pre-built manifest via WP_Block_Metadata_Registry, then block.json decode, then $args; core blocks detected by path prefix skip file_exists entirely 🟢
