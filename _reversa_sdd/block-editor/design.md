## Main Flow

1. **comment-delimited format** — Structure encoded as HTML comments so content degrades gracefully; namespace optional and defaulting to core/; open/close, void and freeform forms.
   Source: `wp-includes/class-wp-block-parser.php:248` 🟢
2. **possessive-quantifier JSON brace matcher** — The attrs sub-pattern uses *+ with two lookaheads to match a JSON object containing } characters, stopping at the } preceding the comment terminator, without catastrophic backtracking.
   Source: `wp-includes/class-wp-block-parser.php:248` 🟢
3. **stack-machine parsing with implicit recovery** — proceed() dispatches on token type; no-more-tokens with a non-empty stack closes every open block implicitly, so parsing never fails.
   Source: `wp-includes/class-wp-block-parser.php:90` 🟢
4. **null-placeholder serialization** — innerContent records the block's own HTML as strings and its children's positions as nulls; serialize_block walks the array substituting each null with the next serialized inner block, giving lossless round-tripping.
   Source: `wp-includes/blocks.php:1794` 🟢
5. **three-source metadata resolution** — Pre-built manifest via WP_Block_Metadata_Registry, then block.json decode, then $args; core blocks detected by path prefix skip file_exists entirely.
   Source: `wp-includes/blocks.php:520` 🟢

## Alternative Flows

- **BR-BLK-05:** Unclosed blocks at end of document are closed implicitly; the parser never fails. 🟢
- **BR-BLK-09:** Blocks under wp-includes/ are treated as core and skip the file_exists() check. 🟢
- **BR-BLK-10:** Core blocks get implicit wp-block-{name} style and wp-block-{name}-editor editorStyle handles, plus wp-block-{name}-theme when wp-block-styles is supported. 🟢
- **BR-BLK-11:** Registration returns false when neither the metadata nor $args supplies a name. 🟢

## Risks and Gaps

- 🟢 **F-BLK-01** — Storing structure in HTML comments means the canonical content format degrades gracefully: an install with the block editor disabled still renders every post correctly. The best design decision in the block system.
- 🟢 **F-BLK-02** — The attribute regex is a hand-rolled JSON brace matcher with a possessive quantifier; content structure is parsed by regular expression, bounding attribute complexity.
- 🟢 **F-BLK-03** — The parser cannot fail: every malformed input maps to freeform or implicit closure, so there is no validation stage and no error signal for corrupt block markup.
- 🟢 **F-BLK-04** — The innerContent null-placeholder design is what makes lossless round-tripping possible; without it nesting position would have to be inferred.
- 🟡 **F-BLK-05** — The metadata manifest exists because reading 115 block.json files per request was measurably slow: a performance workaround visible in the public API surface.
- 🟢 **F-BLK-06** — Dynamic blocks make stored content an incomplete description of the page; two installs with identical post_content can render differently.
