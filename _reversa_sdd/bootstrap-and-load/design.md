## Main Flow

1. **config discovery** — Two-location search for wp-config.php with a guard preventing a nested WordPress from stealing its parent's config.
   Source: `wp-load.php` 🟢
2. **maintenance window self-heal** — Four sequential escape conditions; a stale .maintenance older than 10 minutes is ignored.
   Source: `wp-includes/load.php:437` 🟢
3. **memoized whitelist resolution** — Environment type and development mode both resolve once into a static and fall back to a safe default on any unrecognized value.
   Source: `wp-includes/load.php:250,322` 🟢
4. **paused-extension filtering** — Plugins/themes that fataled are removed from the active list before loading.
   Source: `wp-includes/load.php:1061,1137` 🟢

## Alternative Flows

## Risks and Gaps

- 🟢 **F-BOOT-01** — Boot order is a public contract: 311 requires in fixed sequence with six named checkpoints. Cannot be refactored without breaking the plugin ecosystem.
- 🟢 **F-BOOT-02** — No autoloader for core. Every request pays the cost of loading the whole codebase; SHORTINIT is the only mitigation.
- 🟢 **F-BOOT-03** — Four drop-ins (advanced-cache.php, object-cache.php, db.php, sunrise.php) replace core subsystems by filename convention with no interface validation.
- 🟢 **F-BOOT-04** — Recovery mode is armed before the DB connects, making it capable of surviving almost any failure.
- 🟢 **F-BOOT-05** — wp_magic_quotes() re-slashes superglobals; all WordPress input arrives slashed and wp_unslash() must be called before use. A pervasive correctness trap.
