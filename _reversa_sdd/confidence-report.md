| 3 | `blocks-library` | **BR-BLIB-05** | Cited `wp-includes/blocks/freeform.php`, which **does not exist**. `freeform` is likewise static; the wrapping happens at `blocks.php:1293`. | corrected + 🟢 |
| 4 | `blocks-library` | **BR-BLIB-06** | Location was the glob `wp-includes/blocks/post-*.php`. Replaced with a concrete file plus the count (30 blocks). | precision |
| 5 | `blocks-library` | `primary_files` | Replaced with the real registration files. | precision |
| 6 | `feeds` | **BR-FEED-03** | Location was the glob `wp-includes/feed-*.php`. Replaced with `wp-includes/feed-rss2.php` plus the count. | precision |
| 7 | `ai-abilities-connectors` | dependencies | Declared a dependency on a module named `json-schema`. No such module exists — `wp-includes/json-schema.php` is a **file**. The dependency was removed; schema validation happens in-module. | corrected |

### What these defects have in common

Four of the seven came from **inferring a path from a naming convention** rather than checking the
filesystem, and one from **deriving a statistic from a file count** rather than the authoritative
registration list. Both are the failure modes a reviewer should expect from a structural pass, and
both were caught by mechanical validation against disk.

## 10. Known limits of this analysis

Stated plainly, because a specification that overstates its own reach is worse than one that does not.

1. **No tests exist in this checkout, and the owner has confirmed this is the wrong tree** (Q1 —
   `wordpress-develop` was intended). Every behavioural claim was verified by *reading* code, never
   by executing it. **Nothing in these specifications was confirmed by running WordPress.** This is
   the single most important limitation of the entire extraction.
2. **Coverage is measured in files, not behaviour.** 89.8% of WordPress's own PHP maps to a unit, but
   a unit specifies its *documented rules*, not every line — `formatting.php` alone is 350 KB.
3. **The block editor's client-side behaviour is opaque.** `@wordpress/*` ships as build output only.
4. **Filters make every behavioural claim conditional.** 1,638 filters mean "WordPress does X" is
   always "WordPress does X unless a plugin says otherwise" (F-HOOK-06). Specifications describe the
   **unfiltered default**.
5. **Line numbers drift.** This is an `alpha` branch under active development.
6. **No cross-review by a second engine** was performed; no independent LLM checked this work.
