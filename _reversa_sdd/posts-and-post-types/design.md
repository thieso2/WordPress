## Main Flow

1. **status derived from date** — publish with a date >= 60s ahead becomes future; future with a date < 60s away becomes publish. Status is not caller-controlled.
   Source: `wp-includes/post.php:4800` 🟢
2. **three-scope slug uniqueness** — attachments unique across all types; hierarchical types unique within (type, parent) including attachments; flat types unique within type. Reserved names (feeds, 'embed', pagination numbers, date-archive segments) force a suffix. do-while loop with one query per iteration.
   Source: `wp-includes/post.php:5560` 🟢
3. **dynamic transition hooks** — do_action("{old_status}_to_{new_status}") generates up to 121 undeclared hook names from the 11 built-in statuses.
   Source: `wp-includes/post.php:5914` 🟢
4. **transition side effects** — GUID seeding on first publish, lastpostmodified/lastpostdate cache invalidation across three timezones, post-count cache invalidation, and unconditional publish_future_post cron clearing.
   Source: `wp-includes/post.php:8154` 🟢

## Risks and Gaps

- 🟢 **F-POST-01** — Sixteen semantically unrelated entities share one table and one code path. wp_posts is not a posts table; it is WordPress's generic object store.
- 🟢 **F-POST-02** — Post status is a derived attribute computed from post_date_gmt at write time; any specification treating status as caller-controlled is wrong.
- 🟢 **F-POST-03** — Slug uniqueness uses a query-per-iteration loop with no unique index: slow at scale and racy under concurrency, the same pattern as add_metadata()'s $unique.
- 🟢 **F-POST-04** — The {old}_to_{new} dynamic hook creates up to 121 undeclared hook names that cannot be enumerated by static analysis.
- 🟢 **F-POST-05** — The guid column is documented as a permanent identifier yet seeded from a permalink, the root of long-standing feed-reader confusion.
- 🟢 **F-POST-06** — NO_ZERO_DATE must be stripped from MySQL's SQL mode because drafts store zero dates: two modules' constraints are causally locked together.
- 🟢 **F-POST-07** — post.php is 298 KB in a single file with no class boundary for most of its logic, the largest single unit of coupling in the codebase.
