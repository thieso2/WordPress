## Overview

Make outbound HTTP requests portably, with a safe variant defending against Server-Side Request Forgery. Underlies updates, oEmbed discovery, feeds, the block directory and every plugin calling a remote service. 🟢

**Complexity:** `high` · **Business rules extracted:** 13 · **Public functions catalogued:** 7 · **Extension points:** 9

**Depended on by 10 module(s):** `ai-abilities-connectors`, `authentication-and-sessions`, `cron`, `embeds-oembed`, `feeds`, `filesystem-api`, `rest-api`, `site-health`, `updates-and-upgrader`, `xmlrpc`

## Responsibilities

- **layered SSRF validation** — Type and scheme check, sanitize-and-compare round trip, structural rejections (userinfo, special host characters), same-host exemption, DNS resolution with 13 blocked IPv4 ranges, then a three-port allowlist 🟢
- **sanitize-as-validator** — wp_kses_bad_protocol() output is compared case-insensitively against the original; any difference rejects the URL rather than using the cleaned form 🟢
- **capability-based transport negotiation** — _get_first_available_transport() selects cURL or streams per request based on SSL, proxy and streaming requirements 🟢

## Open points

- 🟡 **F-HTTP-03** — Validation is by resolved IP but the request is made by hostname; a DNS entry resolving differently between check and request (DNS rebinding) defeats the guard, and nothing pins the resolved address.
- 🟡 **F-HTTP-04** — Only IPv4 is range-checked. IPv6 literals are rejected outright, but a hostname resolving to IPv6 is not checked because gethostbyname() returns IPv4 only.
- 🟡 **F-HTTP-06** — The same-host exemption means a site whose home option points at an internal hostname can be used to reach that host.
