## Overview

Classify objects via a three-table design (wp_terms, wp_term_taxonomy, wp_term_relationships) that separates the word from the classification from the assignment. The most normalized part of the WordPress schema and the source of its most confusing API. 🟢

**Complexity:** `high` · **Business rules extracted:** 14 · **Public functions catalogued:** 14 · **Extension points:** 23

**Depended on by 7 module(s):** `blocks-library`, `posts-and-post-types`, `query-and-loop`, `rest-api`, `rewrite-and-permalinks`, `sitemaps`, `widgets-and-nav-menus`

## Responsibilities

- **insert-then-detect-duplicate** — Rows are inserted first, then a SELECT looks for an older row (term_id < new id) with the same slug/parent/taxonomy. If found, the new rows are deleted and the pre-existing ids returned. A compensating transaction implemented without transactions 🟢
- **type-dependent term creation** — In wp_set_object_terms() a string term that does not exist is created via wp_insert_term(); an integer term that does not exist is skipped with no error 🟢
- **static-accumulator deferred counting** — wp_defer_term_counting(true) queues term ids in a static array keyed by taxonomy, flushed in one pass by wp_update_term_count($x,$y,true) 🟢
- **hierarchical count padding** — One join over term_relationships x posts filtered to publish status, building term_items[term_id][object_id]; ancestors are walked with a cycle guard and object ids copied up, deduplicating so a post in child and parent counts once 🟢
- **term_group aliasing** — alias_of joins an existing group or allocates MAX(term_group)+1 and moves the target term into it 🟢
