## Main Flow

1. **insert-then-detect-duplicate** — Rows are inserted first, then a SELECT looks for an older row (term_id < new id) with the same slug/parent/taxonomy. If found, the new rows are deleted and the pre-existing ids returned. A compensating transaction implemented without transactions.
   Source: `wp-includes/taxonomy.php:2645` 🟢
2. **type-dependent term creation** — In wp_set_object_terms() a string term that does not exist is created via wp_insert_term(); an integer term that does not exist is skipped with no error.
   Source: `wp-includes/taxonomy.php:2884` 🟢
3. **static-accumulator deferred counting** — wp_defer_term_counting(true) queues term ids in a static array keyed by taxonomy, flushed in one pass by wp_update_term_count($x,$y,true).
   Source: `wp-includes/taxonomy.php:3587` 🟢
4. **hierarchical count padding** — One join over term_relationships x posts filtered to publish status, building term_items[term_id][object_id]; ancestors are walked with a cycle guard and object ids copied up, deduplicating so a post in child and parent counts once.
   Source: `wp-includes/taxonomy.php:4085` 🟢
5. **term_group aliasing** — alias_of joins an existing group or allocates MAX(term_group)+1 and moves the target term into it.
   Source: `wp-includes/taxonomy.php:2506` 🟢

## Alternative Flows

- **BR-TAX-01:** Objects are linked by term_taxonomy_id, never term_id. One term_id may serve several taxonomies. 🟢
- **BR-TAX-05:** Duplicate detection happens after insert; only a row with a lower term_id counts as the duplicate, and the newly inserted rows are then deleted. 🟢
- **BR-TAX-10:** A taxonomy's update_count_callback overrides the default counting query. 🟢
- **BR-TAX-11:** Hierarchical count padding counts only objects with post_status = 'publish'. 🟢

## Risks and Gaps

- 🟢 **F-TAX-01** — The term_id / term_taxonomy_id split is correct normalization that the API then obscures: most functions take term_id while relationships use tt_id. The module's dominant defect source.
- 🟢 **F-TAX-02** — wp_insert_term() inserts before checking for duplicates and deletes its own rows on conflict: a compensating transaction implemented without transactions, which wpdb does not provide.
- 🟢 **F-TAX-03** — String-creates / integer-skips in wp_set_object_terms() is an undocumented type-dependent behavior difference with no error signal.
- 🟢 **F-TAX-04** — Term assignment costs one existence query per term, so bulk assignment is O(n) queries.
- 🟢 **F-TAX-05** — Hierarchical counts are computed at read time by _pad_term_counts(), so a large category tree pays a term_relationships x posts join on every render.
- 🟡 **F-TAX-06** — The cycle guard in ancestor walking is evidence that corrupted parent chains occur in practice; the schema has no foreign key preventing them.
- 🟡 **F-TAX-07** — term_group / alias_of is a vestigial synonym feature with no UI, superseded in practice by term meta.
