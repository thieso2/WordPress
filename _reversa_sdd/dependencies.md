## 1. Dependency model

WordPress core has **no package manager at runtime**. There is no root `composer.json` and no root `package.json` in this tree.

Every third-party dependency is **vendored** — copied into `wp-includes/` (or `wp-admin/includes/`), namespace-prefixed or wrapped where necessary, and shipped inside the release. Version bumps are manual commits, not lockfile updates.

This is a deliberate architectural decision: WordPress must install by unzipping onto shared hosting with no shell, no Composer and no Node. 🟢

**Consequence:** there is no lockfile to audit, no `composer audit` / `npm audit` to run, and no dependency-resolution graph. Vulnerability tracking for the list below is manual. 🔴 GAP — confirm how this project tracks CVEs in vendored code.

## 2. Runtime platform requirements 🟢

| Requirement | Version | Source |
|-------------|---------|--------|
| PHP | ≥ 7.4 | `$required_php_version` in `wp-includes/version.php` |
| MySQL | ≥ 5.5.5 | `$required_mysql_version` in `wp-includes/version.php` |
| MariaDB | supported alternative | `class-wpdb.php` version detection |

### PHP extensions

| Extension | Requirement | Fallback |
|-----------|-------------|----------|
| `mysqli` | required | none (hard requirement) |
| `json` | required | none |
| `libsodium` / `sodium` | optional | `wp-includes/sodium_compat/` pure-PHP polyfill |
| `gd` or `imagick` | optional (image editing) | `WP_Image_Editor_GD` / `WP_Image_Editor_Imagick`, selected at runtime |
| `curl` | optional (HTTP) | `WP_Http_Streams` fallback transport |
| `zip` / `ZipArchive` | optional (upgrades) | `PclZip` pure-PHP fallback |
| `mbstring` | optional | `wp-includes/compat.php` polyfills |
| `openssl` | optional (HTTPS) | bundled CA cert in `wp-includes/certificates/` |

The optional-with-fallback pattern is pervasive and is a load-bearing part of the architecture: WordPress assumes it cannot control its hosting environment. 🟢

### PHP AI Client — worth calling out 🟢

`wp-includes/php-ai-client/` (146 files) is by far the largest vendored library and the newest. Its structure:

```
src/
├── AiClient.php              facade
├── Builders/                 fluent prompt construction
├── Messages/                 message + part model
├── Providers/                provider abstraction
│   ├── AbstractProvider.php
│   ├── ProviderRegistry.php
│   ├── ApiBasedImplementation/
│   ├── OpenAiCompatibleImplementation/
│   ├── Contracts/, DTO/, Enums/, Http/, Models/
├── Tools/                    function/tool calling
├── Files/, Results/, Operations/, Events/, Common/
third-party/                  Http/, Nyholm/, Psr/  (PSR-7/17/18 implementations)
```

WordPress wraps it in `wp-includes/ai-client/` (6 files: cache, discovery strategy, event dispatcher, HTTP client adapters) and exposes it through `wp-includes/ai-client.php`, `abilities.php`, `abilities-api/` and `connectors.php`.

### `@wordpress/*` packages — pre-built 🟢

`wp-includes/js/dist/` ships the compiled Gutenberg packages (`blocks`, `block-editor`, `block-library`, `components`, `data`, `element`, `api-fetch`, `i18n`, `a11y`, `compose`, `commands`, `annotations`, `autop`, `blob`, `block-directory`, `block-serialization-*`, and ~50 more), each in dev and `.min` form.

**Their source is not in this tree.** They are built from the `gutenberg` / `wordpress-develop` repositories. Reverse-engineering the editor's JS behavior from `js/dist/` means reading minified or bundled output. 🔴 GAP — the block editor's client-side logic is effectively opaque to this analysis; specs covering editor UX must be marked 🟡 INFERRED at best.

## 5. Bundled themes 🟢

14 default themes in `wp-content/themes/`:

`twentyten`, `twentyeleven`, `twentytwelve`, `twentythirteen`, `twentyfourteen`, `twentyfifteen`, `twentysixteen`, `twentyseventeen`, `twentynineteen`, `twentytwenty`, `twentytwentyone`, `twentytwentytwo`, `twentytwentythree`, `twentytwentyfour`, `twentytwentyfive`

Five carry their own `package.json` + `package-lock.json` (theme-local SCSS/PostCSS builds): `twentynineteen`, `twentytwenty`, `twentytwentyone`, `twentytwentytwo`, `twentytwentyfive`. These are the only npm manifests anywhere in the tree, and they build theme assets only — not core. 🟢

`twentytwentytwo` onward are block themes (`theme.json` + `templates/` + `patterns/`); earlier ones are classic PHP-template themes. 🟢

## 7. What is absent 🟢

| Expected in a modern PHP project | Present? |
|----------------------------------|----------|
| `composer.json` / `composer.lock` at root | ❌ |
| `package.json` at root | ❌ |
| Autoloader (PSR-4) | ❌ — core uses explicit `require` (311 in `wp-settings.php`); only vendored libs autoload |
| Dependency injection container | ❌ — global functions + global `$wpdb`, `$wp_query`, `$wp_rewrite`… |
| ORM / query builder | ❌ — `wpdb` with hand-written SQL and `prepare()` |
| Migration framework | ❌ — `dbDelta()` + version-gated `upgrade_NNN()` functions |
| Test suite | ❌ — lives in `wordpress-develop` |
| CI configuration | ❌ |
| Container definition | ❌ |
| Static analysis config (PHPStan/Psalm) | ❌ in this tree — recent commit history references a PHPStan baseline, so it exists upstream 🟡 |

The absence list is not a deficiency report. It is the shape of the system: WordPress predates all of these conventions and has kept backward compatibility with the hosting environments that made them impossible.

## 8. Dependency risk notes

| # | Note | Confidence |
|---|------|-----------|
| 1 | No lockfile anywhere in core ⇒ no automated vulnerability scanning path for the 13 vendored PHP libraries. | 🟢 |
| 2 | `class-snoopy.php` is a deprecated HTTP client still shipped. Dead weight with a network surface. | 🟡 |
| 3 | `sodium_compat` performs Ed25519 verification of update packages. It is security-critical and pure PHP. | 🟢 |
| 4 | React is pinned at a WordPress-local patch build (`18.3.1.1`), so it does not track upstream React releases directly. | 🟢 |
| 5 | jQuery 3.7.1 + jQuery Migrate 3.4.1 are still loaded, meaning core still carries pre-2015 admin JS patterns. | 🟢 |
| 6 | `@wordpress/*` packages ship only as build output; their source and their own dependency tree are outside this repo. | 🔴 GAP |
