## Identified Design Decisions

| Decision | Evidence in the code | Confidence |
|----------|----------------------|------------|
| Each support's apply callback returns attributes; scalars (excluding booleans) are appended space-separated to any existing value for the same attribute name, letting 23 modules compose without coordination | `wp-includes/class-wp-block-supports.php:114` | 🟢 |
| Supports apply only to blocks with a registered block type; unregistered blocks receive nothing | `wp-includes/class-wp-block-supports.php:120` | 🟢 |
| Attributes contributed by multiple supports are space-concatenated, with the first writer taking the slot and later ones appending | `wp-includes/class-wp-block-supports.php:148` | 🟢 |
| Non-scalar values and booleans are skipped entirely; the explicit is_bool() check prevents true stringifying to '1' in markup | `wp-includes/class-wp-block-supports.php:143` | 🟢 |
| A support without an apply callback contributes nothing at render time, though it may still register attributes | `wp-includes/class-wp-block-supports.php:131` | 🟢 |
| Attributes pass through prepare_attributes_for_render() so schema defaults are applied before any support sees them | `wp-includes/class-wp-block-supports.php:126` | 🟢 |
| The block currently being rendered is tracked in the public static $block_to_render | `wp-includes/class-wp-block-supports.php:43` | 🟢 |

## Risks and Gaps

- 🟢 **F-BSUP-01** — The space-concatenation merge makes 23 independent modules composable without coordination, but registration order affects emitted class order.
- 🟡 **F-BSUP-02** — The explicit is_bool() exclusion is a bug fix visible in the code: is_scalar() alone would have injected '1' into markup.
- 🟢 **F-BSUP-03** — $block_to_render as a public static means block rendering is not reentrant at the supports layer without saving and restoring it.
