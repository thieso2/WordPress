## Overview

Prove identity and maintain it across requests: password hashing, cookie-based sessions, session tokens, nonces, and the pluggable-function override mechanism. 🟢

**Complexity:** `high` · **Business rules extracted:** 16 · **Public functions catalogued:** 17 · **Extension points:** 20

**Depended on by 4 module(s):** `admin-application`, `error-handling-and-recovery-mode`, `rest-api`, `xmlrpc`

## Responsibilities

- **bcrypt pre-hashing** — base64(hmac_sha384(password, 'wp-sha384')) fed to password_hash(), prefixed '$wp'. Preserves entropy beyond bcrypt's 72-byte limit with domain separation and no null bytes 🟢
- **two-stage cookie HMAC** — wp_hash(user_login|pass_frag|expiration|token, scheme) derives a per-user key; that key HMAC-SHA256s user_login|expiration|token. The password fragment is never transmitted but changing it invalidates all cookies 🟢
- **half-life nonce ticks** — tick = ceil(time() / (nonce_life/2)); verification accepts tick and tick-1, returning 1 or 2 to signal age. Nonces are deterministic within a 12-hour window 🟢
- **pluggable override** — Every function wrapped in if (! function_exists()); pluggable.php loads after all plugins so any plugin can replace the entire security core 🟢
