## Main Flow

1. **bcrypt pre-hashing** — base64(hmac_sha384(password, 'wp-sha384')) fed to password_hash(), prefixed '$wp'. Preserves entropy beyond bcrypt's 72-byte limit with domain separation and no null bytes.
   Source: `wp-includes/pluggable.php:2771` 🟢
2. **two-stage cookie HMAC** — wp_hash(user_login|pass_frag|expiration|token, scheme) derives a per-user key; that key HMAC-SHA256s user_login|expiration|token. The password fragment is never transmitted but changing it invalidates all cookies.
   Source: `wp-includes/pluggable.php:951` 🟢
3. **half-life nonce ticks** — tick = ceil(time() / (nonce_life/2)); verification accepts tick and tick-1, returning 1 or 2 to signal age. Nonces are deterministic within a 12-hour window.
   Source: `wp-includes/pluggable.php:2444` 🟢
4. **pluggable override** — Every function wrapped in if (! function_exists()); pluggable.php loads after all plugins so any plugin can replace the entire security core.
   Source: `wp-includes/pluggable.php` 🟢

## Alternative Flows

- **BR-AUTH-02:** Passwords longer than 4096 bytes hash to '*', which never verifies. A DoS guard expressed as a permanently failing hash. 🟢
- **BR-AUTH-06:** The password fragment is substr(hash, 8, 4) for $P$ and $2y$ hashes and substr(hash, -4) otherwise. 🟢
- **BR-AUTH-10:** The logged_in cookie is only marked secure when the auth cookie is secure AND the home URL uses HTTPS. 🟢
- **BR-AUTH-13:** wp_verify_nonce() returns 1 (0-12h old), 2 (12-24h old) or false, never true. 🟢
- **BR-AUTH-16:** Logged-out users all share uid 0 for nonce generation unless the nonce_user_logged_out filter supplies an identity. 🟢

## Risks and Gaps

- 🟢 **F-AUTH-01** — The entire authentication stack is pluggable with no interface contract, so 'how does WordPress authenticate?' is unanswerable without knowing the plugin set.
- 🟢 **F-AUTH-02** — Password-fragment-in-key-derivation gives password-change-invalidates-sessions without any server-side session store; a stolen cookie survives exactly until the password changes.
- 🟢 **F-AUTH-03** — Nonces are deterministic within a 12-hour window, making them CSRF tokens rather than nonces; they are replayable within that window.
- 🟢 **F-AUTH-04** — wp_verify_nonce() returning 1/2/false is a truthiness trap: === true always fails and the stale-nonce signal (2) is almost universally discarded.
- 🟡 **F-AUTH-05** — 40 bits of nonce entropy is adequate for CSRF given action and user binding but far below what the name suggests.
- 🟢 **F-AUTH-06** — All logged-out users share a single nonce value per action, so anonymous-facing nonces provide no per-user CSRF protection by default.
- 🟢 **F-AUTH-07** — The bcrypt pre-hashing scheme is a careful, correct solution to the 72-byte truncation, handling both domain separation and null-byte avoidance.
- 🟡 **F-AUTH-08** — The one-hour POST/AJAX grace period silently extends session validity precisely for state-changing requests, a usability decision with an undocumented security cost.
