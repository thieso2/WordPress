## Overview

WordPress's HTTP API. A route registry, a dispatcher with a schema-driven validate/sanitize pipeline, and 49 controllers exposing core entities at /wp-json/. 🟢

**Complexity:** `high` · **Business rules extracted:** 11 · **Public functions catalogued:** 8 · **Extension points:** 12

**Depended on by 2 module(s):** `ai-abilities-connectors`, `site-health`

## Responsibilities

- **validate-then-sanitize dispatch** — match route, verify callable handler, has_valid_params() then sanitize_params(), both schema-driven from the route's args; any failure short-circuits to an error response without invoking the callback 🟢
- **fail-closed permission gate** — permission_callback returning false or null denies with 401/403 depending on login state; but an ABSENT callback skips the gate entirely, making the route public 🟢
- **reentrant dispatch stack** — $dispatching_requests is pushed on entry and popped at every exit path, allowing nested internal REST requests 🟢
