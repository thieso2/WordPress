## Main Flow

1. **validate-then-sanitize dispatch** — match route, verify callable handler, has_valid_params() then sanitize_params(), both schema-driven from the route's args; any failure short-circuits to an error response without invoking the callback.
   Source: `wp-includes/rest-api/class-wp-rest-server.php:1062` 🟢
2. **fail-closed permission gate** — permission_callback returning false or null denies with 401/403 depending on login state; but an ABSENT callback skips the gate entirely, making the route public.
   Source: `wp-includes/rest-api/class-wp-rest-server.php:1250` 🟢
3. **reentrant dispatch stack** — $dispatching_requests is pushed on entry and popped at every exit path, allowing nested internal REST requests.
   Source: `wp-includes/rest-api/class-wp-rest-server.php:1063` 🟢

## Observability

- BR-REST-07 — register_rest_route() called before rest_api_init emits _doing_it_wrong() and the route is not registered. `wp-includes/rest-api.php:138`
- BR-REST-08 — A missing permission_callback emits _doing_it_wrong() recommending __return_true, but this is a notice and the route still serves. `wp-includes/rest-api.php:127`

## Risks and Gaps

- 🟢 **F-REST-01** — The most consequential rule is that a missing permission_callback means public. The safe default would be denial; instead core warns and serves.
- 🟢 **F-REST-02** — Treating null as denial catches the common 'forgot to return' bug and is the opposite polarity to map_meta_cap()'s 'empty caps means allowed': two authorization layers in core with opposite defaults.
- 🟢 **F-REST-03** — rest_pre_dispatch bypasses the permission check along with everything else, making it a complete authorization bypass by design.
- 🟢 **F-REST-04** — 49 controllers plus 5 field classes and 4 search handlers make this the largest specified surface in WordPress and the only subsystem with machine-readable schemas, which is why OpenAPI generation is feasible here and nowhere else.
- 🟢 **F-REST-05** — The schema-driven validate-then-sanitize pipeline is stricter and more uniform than the classic side, where each $_POST handler validates ad hoc.
