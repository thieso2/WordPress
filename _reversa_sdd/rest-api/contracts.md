## Risks

- 🟢 **F-REST-01** — The most consequential rule is that a missing permission_callback means public. The safe default would be denial; instead core warns and serves.
- 🟢 **F-REST-02** — Treating null as denial catches the common 'forgot to return' bug and is the opposite polarity to map_meta_cap()'s 'empty caps means allowed': two authorization layers in core with opposite defaults.
- 🟢 **F-REST-03** — rest_pre_dispatch bypasses the permission check along with everything else, making it a complete authorization bypass by design.
- 🟢 **F-REST-04** — 49 controllers plus 5 field classes and 4 search handlers make this the largest specified surface in WordPress and the only subsystem with machine-readable schemas, which is why OpenAPI generation is feasible here and nowhere else.
- 🟢 **F-REST-05** — The schema-driven validate-then-sanitize pipeline is stricter and more uniform than the classic side, where each $_POST handler validates ad hoc.
