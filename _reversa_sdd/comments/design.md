## Main Flow

1. **duplicate detection** — Concatenated prepare() fragments matching post, parent, author, optional email and exact content, excluding trashed comments. A hit terminates with HTTP 409.
   Source: `wp-includes/comment.php:752` 🟢
2. **flood window query with defaulting-false verdict** — One-hour lookback keyed on user_id or IP, OR email; the verdict is delegated to comment_flood_filter which core never sets true.
   Source: `wp-includes/comment.php:909` 🟢
3. **four-rule moderation** — Manual moderation short-circuit, link-count threshold, keyword substring match across six fields, previously-approved requirement.
   Source: `wp-includes/comment.php:43` 🟢
4. **post-decision disallowed override** — The disallowed list runs after the approval decision and overrides it, choosing trash or spam based on EMPTY_TRASH_DAYS.
   Source: `wp-includes/comment.php:1398` 🟢

## Alternative Flows

- **BR-CMT-02:** Users with manage_options or moderate_comments are never flood-throttled. 🟢
- **BR-CMT-03:** Flood detection looks back one hour, matched by user_id when logged in, otherwise by IP, or by email in either case. 🟢
- **BR-CMT-04:** The flood verdict defaults to false; core supplies only the query and the comment_flood_filter hook. No rate limit is enforced by core itself. 🟢
- **BR-CMT-09:** comment_previously_approved = '1' requires a prior approved comment, matched by user_id for registered users or by author name AND email otherwise. 🟢
- **BR-CMT-10:** A disallowed-list match overrides any approval and sets the status to 'trash' if EMPTY_TRASH_DAYS is truthy, otherwise 'spam'. 🟢

## Risks and Gaps

- 🟢 **F-CMT-01** — Core ships no working rate limit. wp_check_comment_flood() performs a query then asks a filter that defaults to false; the feature reads as protection but provides none without a plugin.
- 🟢 **F-CMT-02** — Moderation keywords match as unquoted substrings across six fields including IP and user agent, so short keywords produce heavy false positives.
- 🟢 **F-CMT-03** — The disallowed list overrides the approval decision after it is made, so pipeline ordering rather than rule content determines the outcome.
- 🟢 **F-CMT-04** — Whether a disallowed comment becomes trash or spam depends on EMPTY_TRASH_DAYS, an unrelated constant; disabling trash silently changes spam handling.
- 🟢 **F-CMT-05** — comment_approved as a string mixing booleans and state names forces every consumer to string-compare, with endemic '0' == false traps.
- 🟡 **F-CMT-06** — Length validation is inconsistent: two fields use mb_strlen(v,'8bit') and two use strlen(). Both count bytes, but the asymmetry suggests character counting was intended in the first pair.
- 🟢 **F-CMT-07** — Moderation inspects text already filtered by comment_text, so a rendering plugin can inadvertently change what the spam filter sees.
