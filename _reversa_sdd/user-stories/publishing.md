## US-PUB-01 — Publish a post immediately

**As an** Author
**I want** to publish a post
**So that** visitors can read it

### Acceptance criteria

```gherkin
Given I hold the `publish_posts` capability
And I am the author of the post
When I publish a post whose date is now or in the past
Then post_status becomes 'publish'                                    # BR-POST-01
And a slug is generated and made unique within the post type          # BR-POST-06
And the guid column is seeded from get_permalink(), once and forever  # BR-POST-10
And transition_post_status and draft_to_publish both fire             # BR-POST-09
And the lastpostmodified caches are invalidated for 3 timezones       # _transition_post_status
And any pending publish_future_post cron event is cleared             # BR-POST-11
```

**Blocked for:** Contributor — lacks `publish_posts` 🟢

## US-PUB-02 — Schedule a post for later

**As an** Editor
**I want** to schedule a post
**So that** it publishes without me being present

```gherkin
Given I set the post date at least 60 seconds in the future
When I click Publish
Then post_status is silently converted to 'future'                    # BR-POST-01
And a publish_future_post cron event is scheduled for that timestamp
And no slug uniqueness is skipped — 'future' is not a draft status    # BR-POST-05

Given the scheduled time arrives
When any visitor loads any page of the site
Then spawn_cron() fires wp-cron.php and the post publishes            # BR-CRON-11

Given the scheduled time arrives
And the site receives NO traffic
Then the post does NOT publish                                        # F-CRON-01 ⚠️
```

**This is the single most surprising behaviour in WordPress for content teams.** 🟢

## US-PUB-03 — Save a draft

```gherkin
Given I am a Contributor
When I save a draft
Then post_status is 'draft'
And post_date_gmt is stored as '0000-00-00 00:00:00'                  # BR-POST-04
And NO slug is generated                                              # BR-POST-05
And the database must be running without NO_ZERO_DATE                 # BR-DB-10, ADR-007
```

🟡 The zero-date storage is invisible to the user but constrains the entire database
configuration.

## US-PUB-04 — Add an image to a post

```gherkin
Given I hold the `upload_files` capability
When I upload an image
Then an 'attachment' post is created with status 'inherit'            # BR-POST-03
And one file is written per registered subsize                        # BR-MEDIA-10
And no subsize larger than the original is generated                  # BR-MEDIA-01
And _wp_attachment_metadata records dimensions, subsizes and EXIF

Given I am a Contributor
When I try to upload
Then I am denied — Contributor has no `upload_files` capability       # BR-CAP-15 ⚠️
```

## US-PUB-05 — Categorise a post

```gherkin
Given I assign an existing category by term_id
When the post is saved
Then a row is written to wp_term_relationships using the TERM_TAXONOMY_ID  # BR-TAX-01
And the term count is updated (or deferred if counting is deferred)         # BR-TAX-09

Given I assign a category that does not exist, passed as a STRING
When the post is saved
Then the term is CREATED                                                    # BR-TAX-06

Given I assign a category that does not exist, passed as an INTEGER
When the post is saved
Then it is SILENTLY SKIPPED with no error                                   # BR-TAX-06 ⚠️
```

🟢 The string-creates / integer-skips asymmetry is undocumented and silent (F-TAX-03).

## US-PUB-06 — Trash and restore

```gherkin
Given a published post
When I trash it
Then post_status becomes 'trash'
And _wp_trash_meta_status records the previous status
And its comments become 'post-trashed'                                # BR-CMT-12

When I restore it
Then the previous status is read back from _wp_trash_meta_status
And its comments return to their prior approval state

Given EMPTY_TRASH_DAYS has elapsed
When wp_scheduled_delete runs
Then the post is permanently deleted
```

## US-PUB-07 — Edit with blocks

```gherkin
Given I edit a post in the block editor
When I save
Then post_content is stored as VALID HTML with comment delimiters      # ADR-008
And the content renders correctly even with the block editor disabled  # F-BLK-01

Given post_content contains a block type that is not registered
When the post renders
Then the 'missing' block renders a placeholder and PRESERVES the content # BR-BLIB-04

Given post_content contains malformed block markup
When it is parsed
Then the parser NEVER fails — unclosed blocks close implicitly          # BR-BLK-05
And unrecognised text becomes a core/freeform block                     # BR-BLK-04
```
