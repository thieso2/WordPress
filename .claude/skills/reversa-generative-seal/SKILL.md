# Generative Seal

Creates **unique, reproducible visual seals** for Reversa projects using p5.js. Each project gets its own generative artwork derived from a deterministic seed: the same seed always produces the same seal.

Inspired by the Art Blocks pattern (seeded randomness) and Anthropic's `algorithmic-art` skill, but with a deliberately smaller scope: it produces **only the seal**, not a philosophical manifesto, not an exploration platform. It is a decorative identity element.

## When to use it

- **The hero of the `index.html`** in the mini-site generated by `/reversa-documentation`.
- **A mini-seal in the header** of every mini-site page (a reduced version).
- **A slide cover** in `deck.html`.
- **A visual identity** for any Reversa-generated artifact that needs a distinctive mark.

The skill is **lightweight by design**: it uses only p5.js, generates a single canvas, and exports as SVG or PNG. It has no exploration sidebar, no multiple modes, and no mandatory animation (animation is optional).

## Principles
1. **Absolute reproducibility**: the same seed always produces the same seal.
2. **A limited palette**: 3 to 5 colors per seal, derived from the chosen visual style.
3. **Balanced composition**: a recognizable central form with auxiliary elements orbiting or composing around it.
4. **No text on the canvas**: the seal is purely visual; the project's name and title live outside the canvas, in HTML.
5. **Size-adaptable**: the same canvas works at 64x64 (a header mini-seal) and at 800x800 (a large hero).
6. **No dependencies beyond p5.js**: no GSAP, dat.GUI or lodash. Just p5.

## Workflow

### 1. Receiving the seed

The seed may come from:

- **A direct string**: the user or the agent passes a sha256 hash, a project name, or any string.
- **A file path**: the user points at `.reversa/soul.md` and the skill computes the `sha256` of its content.
- **A fallback**: if nothing is provided, use the `sha256` of the current timestamp (a "seal of the moment", not reproducible).

```javascript
async function computeSeed(input) {
    const enc = new TextEncoder();
    const data = enc.encode(input);
    const hashBuffer = await crypto.subtle.digest("SHA-256", data);
    const hashArray = Array.from(new Uint8Array(hashBuffer));
    const hashHex = hashArray.map((b) => b.toString(16).padStart(2, "0")).join("");
    return hashHex;
}
```

The seed is a 64-character hexadecimal string. The skill extracts several numbers from it to feed distinct parameters.

### 2. Choosing the palette

The palette derives from the visual style the user chose in `/reversa-documentation`, or it can be supplied directly.

Consult `references/PALETTE_BY_STYLE.md` for the full table of palettes per style. The 4 base palettes are:

| Style | Palette |
|--------|--------|
| `sober` | Neutral tones: grays, petrol blue, light terracotta, off-white |
| `premium` | Dark mode: deep black, gold, wine red, silver, midnight blue |
| `dense` | Saturated: orange, cyan, magenta, lime, indigo |
| `exploratory` | Luminous pastels: aurora pink, glacier cyan, mist lilac, light white |

Which color is "central" and which are "auxiliary" comes from the seed.

### 3. Choosing the generative pattern

The skill has **5 established patterns**, each with a distinct look. The seed decides which pattern to use (the first 2 hex digits modulo 5):

| Pattern | Look | What it pairs with |
|--------|-----------|----------------|
| `flow-field` | Perlin flow fields, organic curved strokes | The `sober`, `exploratory` styles |
| `particle-orbit` | Particles orbiting a center with trails | The `premium`, `exploratory` styles |
| `crystal-lattice` | A symmetric crystalline form, clean geometry | The `dense`, `sober` styles |
| `wave-interference` | Moiré-style interference patterns, circular waves | The `premium`, `dense` styles |
| `noise-strata` | Horizontal noise strata, an abstract landscape | The `sober`, `exploratory` styles |

Details in `references/GENERATIVE_PATTERNS.md`.

The skill can accept a pattern override via a parameter, ignoring the seed-based derivation.

### 4. Generating the code

The structure of the resulting HTML:

```html
<html lang="en">
<html lang="pt-BR">
<head>
    <title>Seal: <!-- PROJECT_NAME --></title>
    <title>Selo: <!-- PROJECT_NAME --></title>
    <script src="https://cdnjs.cloudflare.com/ajax/libs/p5.js/1.9.0/p5.min.js"></script>
    <style>
        body { margin: 0; display: flex; align-items: center; justify-content: center; min-height: 100vh; background: var(--seal-bg, #0a0a14); }
        #seal-container { display: block; }
        .label { color: var(--seal-fg, #eaeaea); text-align: center; margin-top: 16px; font-family: system-ui, sans-serif; }
    </style>
</head>
<body>
    <div>
        <div id="seal-container"></div>
        <div class="label"><!-- PROJECT_NAME --></div>
    </div>
    <script id="seal-config" type="application/json">
        <!-- CONFIG_JSON -->
    </script>
    <script>
        // 1. Read the config (seed, palette, pattern, size)
        // 2. Seedar p5.js: randomSeed(seedInt); noiseSeed(seedInt);
        // 3. Run the chosen pattern
        // 4. Save the canvas as a reference
    </script>
</body>
</html>
```

**Fundamental rules**:

1. **Standalone HTML**: a single file, p5.js via CDN, nothing else external.
2. **p5.js 1.9.0+**: use `https://cdnjs.cloudflare.com/ajax/libs/p5.js/1.9.0/p5.min.js`.
3. **Always seeded**: `randomSeed(seedInt)` and `noiseSeed(seedInt)` in the first setup, before any call to `random()` or `noise()`.
4. **Converting a hex hash to an int**: take the first 16 hex chars and convert via `parseInt(hex.slice(0, 16), 16)`.
5. **A square canvas**: 800x800 by default, but parameterizable.
6. **noLoop()**: by default the seal is static. If animation is requested, use `frameRate(30)` and a low-cost algorithm.
7. **No text on the canvas**: the project's name goes in a `<div class="label">` outside the canvas.

### 5. Size variants

The skill accepts a `size` parameter to generate a large seal (a hero, 800x800), a medium one (a slide cover, 400x400) or a mini one (a header, 64x64 or 128x128).

On smaller seals (<200px), apply automatic simplifications:
- Reduce the particle count by 80%.
- Increase the stroke thickness proportionally.
- Disable the animation.

## Quality guidelines

- **Recognizability**: the seal must have a strong central form; whoever has seen it once should recognize the project by its seal.
- **Chromatic balance**: never use every color in the palette on the same seal; typically 1 dominant color (60%), 1 secondary (30%), 1 accent (10%).
- **Do not draw more attention than the content**: the seal is identity, not the focus. In a large hero it can be the protagonist; in a header mini-seal it must give way to the project's name.
- **Accessibility**: a minimum contrast between the background and the primary elements. Seals with a dark background have light elements, and vice versa.
- **Language**: comments follow the installation's language, with no em dashes.

## Code guidelines

- **Named constants at the top**: the size, the palette and the pattern's parameters visible at the start.
- **A single generation function**: each pattern is a `drawFlowField()`, `drawCrystalLattice()`, etc. function, isolated and testable.
- **No global side effects**: everything scoped inside p5's `setup()` and `draw()`.

## Error handling

Consult `references/ERRORS.md` for the scenarios (p5.js unavailable, canvas unsupported, an invalid seed, an extreme size).
